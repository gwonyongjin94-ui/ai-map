# AI Map

전 세계 AI 기업을 지도 위에서 한눈에 보는 웹 서비스.

- **기업 지도**: 아이콘을 누르면 회사 소개, 이끄는 사람, 주력 AI 제품, 상장 정보와 지연 주가, 기업별 최신 뉴스
- **AI 브리핑**: 최근 72시간 동안 모든 기업의 뉴스를 모아 Claude가 같은 사건끼리 묶고 한국어로 요약한 "오늘의 이슈". 이슈를 누르면 관련 기업이 지도에서 강조되고 서로 선으로 이어진다.
- **비교 보드** (`#board`): 상장사 29곳을 한 화면에서 비교. 기간(1일·1개월·3개월·YTD·1년)과 분야 필터가 아래 전부에 적용된다.
  - 시가총액 히트맵: 크기 = 시가총액(달러 환산), 색 = 기간 수익률 (상승 빨강 · 하락 파랑, 7단계)
  - 수익률 비교 차트: 기간 시작일을 0%로 맞춘 누적 수익률, 최대 6개 기업 (히트맵 타일·표 체크로 추가)
  - 전체 종목 표: 정렬, 52주 범위, PER, 기간 추이
- **관계도** (`#relations`): 56개 기업 사이의 투자·반도체 공급·클라우드 계약·제휴·창업자 출신·인수 관계 105개를 네트워크로 표시. 기업을 누르면 그 기업의 관계만 보이고, 같은 내용을 표로도 볼 수 있다. 지도의 기업 상세에도 "관계" 탭과 지도 연결선이 있다.
- **모델 타임라인** (`#models`): 2022년 11월 ChatGPT부터 지금까지 지도에 있는 기업이 낸 주요 모델 209개. 기업별 출시 흐름 차트(종류별 색, 속이 빈 점 = 오픈 웨이트, 테두리 = 주요 출시)와 연도별 목록, 종류·오픈 웨이트·주요 출시·기업 필터. 지도의 기업 상세에도 "모델" 탭이 있다.
- **AI 성능 비교** (`#bench`, 모델 화면의 "성능 비교" 탭): [Epoch AI](https://epoch.ai/benchmarks)가 모은 시험 점수로 모델 317개를 비교한다. 시험은 종합 능력 지수(ECI)·과학(GPQA Diamond)·수학(FrontierMath)·코딩(FrontierCode)·퍼즐(ARC-AGI-2)·최고난도(Humanity's Last Exam)·사실(SimpleQA Verified) 7개. 시험마다 무엇을 재는지, 읽는 법, 주의할 점과 근거 링크를 보여 주고, 점수 출처를 "Epoch 측정"(Epoch이 같은 방식으로 직접 시험)·"외부 집계"(시험 만든 곳의 리더보드)·"추정"(ECI, 통계 모형 값이라 흐리게 "약 …")으로 구분한다. 순위에는 오차 범위(ECI는 90% 신뢰구간, 나머지는 95%)를 가는 선으로 그리고, 1·2위 구간이 겹치면 "누가 낫다고 말하기 어렵다"고 적는다. 찍기(25%)·사람 기준선이 있는 시험은 점선으로 표시한다. 아래 차트는 출시일별 점수와 비공개·오픈 웨이트 최고 기록의 흐름. 회사별 최고 모델만·오픈 웨이트만·관심 기업만·기업 필터.
- **주간 리포트** (`#report`): AI 브리핑에 실린 이슈를 날짜별로 보관하고 한 주(월~일)씩 보여준다. 많이 나온 기업·분야, 그 주에 나온 모델(모델 타임라인 기준), 날짜별 이슈와 원문 기사. 한 주가 끝나면 Claude가 그 주를 3~4문장으로 정리한다. 브리핑 사이드바 아래 "지난 브리핑 · 주간 리포트"로도 들어간다.
- **AI 데이터센터 지도**: 지도 왼쪽 위 "데이터센터" 버튼이나 사이드바 "데이터센터" 탭으로 세계 주요 AI 데이터센터 104곳을 지도에 얹는다. 네모 핀 크기는 계획 전력, 채움은 상태(가동 · 일부 가동·증설 중 · 건설 중 · 계획)다. 누르면 지금/계획 전력, 가동 시점, 칩, 전력 공급, 운영·사용 기업, 근거 자료(기사·인허가·공시 링크)와 Epoch의 날짜별 위성 확인 기록이 나오고 그 기업 본사로 선이 이어진다(운영 실선, 사용 점선). 기본은 **확인된 곳**(86곳)만 보여주고, 운영사 미공개·유력·계획 단계인 곳은 "전체"에서 흐리게 보인다. 위성 사진으로 계산한 **추정**·**예상** 숫자는 흐리게("약 …"), 회사 **발표**·언론 **보도** 숫자는 진하게 표시한다. 기업 상세에도 "AI 데이터센터" 항목이 생긴다. 대부분 Epoch AI의 위성·인허가 기반 추정치(CC BY 4.0)이고, 한국(SK·AWS 울산, 네이버 각 세종, 카카오 안산, 스타게이트 코리아 계획)·일본·인도·프랑스 몇 곳과 Epoch에 아직 없는 미국 구글 웨스트멤피스(아칸소)는 공식 발표·공개 보도로 보탰다. 전력 규모를 공개하지 않은 곳은 숫자를 "공개 안 됨"으로 비워 둔다.
- **AI 전력 (발전소·전력 회사)**: 지도 왼쪽 위 "발전소" 버튼이나 사이드바 "전력" 탭. AI 기업이 장기 전력구매계약을 맺었거나 데이터센터 옆에 짓는 발전소 16곳(원전 재가동·장기 계약, 차세대 원전·핵융합, 데이터센터 전용 가스 발전)과 전력 회사 26곳. 마름모 핀 안 그림은 연료(원자력·차세대 원자력·천연가스), 채움은 상태다. 발전소를 누르면 규모(발표·보도 구분), 계약, 설명, 근거 자료가 나오고 전기를 받는 데이터센터(실선)와 사는 기업 본사(점선)로 선이 이어진다. 전력 회사를 누르면 본사에서 운영 발전소·공급 데이터센터·계약 기업으로 선이 이어진다. 확인된 곳(실제로 있거나 공사 중, 12곳)이 기본이고 계획·승인 단계는 "전체"에서 흐리게 보인다. 데이터센터 상세에는 "전력", 기업 상세에는 "전력 계약" 항목이 생긴다.
- **관심 기업** (`#watchlist`): 기업 상세의 ☆로 별표를 달면, 별표한 기업마다 주가·최근 뉴스·오늘의 브리핑·최근 모델·관계를 카드 하나로 모아 보여준다. 지도 목록의 "★ 관심" 칩, 모델 타임라인·주간 리포트의 "관심 기업만" 스위치로 별표한 기업만 골라 볼 수 있고, 지도 핀(과 그 핀이 묶인 클러스터)과 브리핑 카드에 ★가 붙는다. 별표는 이 브라우저의 localStorage(`aimap-favorites`)에만 저장되고 서버로 보내지 않는다. 다른 탭에서 바꾸면 바로 반영된다.
- **데이터 점검** (`/admin.html`, 이 컴퓨터에서만): 기업 정보가 낡았는지 12시간마다 자동으로 확인해 변경 제안을 만들고, 검토 후 반영·되돌리기

## 실행

```bash
npm install
npm start
```

http://localhost:5173 에서 열린다. Node 20.12 이상이 필요하다. (`PORT` 환경변수로 포트 변경)

### 맥 켤 때 자동 실행

이 맥에서는 launchd(`~/Library/LaunchAgents/com.aimap.server.plist`)가 로그인할 때 서버를 켜고, 서버가 꺼지면 30초 안에 다시 켠다. 맥이 잠자는 동안에는 멈췄다가 깨어나면 이어서 돈다. 로그는 `~/Library/Logs/ai-map.log`. 이 서버가 돌고 있으면 `npm start`는 포트가 겹치니 하지 않는다.

- 화면 파일(`public/`)과 데이터 파일은 새로고침만 하면 바뀐다. 서버 코드(`server.js`, `lib/`)를 고쳤으면 다시 시작한다: `launchctl kickstart -k gui/$(id -u)/com.aimap.server`
- 잠깐 멈추기(다음 로그인 때 다시 켜짐): `launchctl bootout gui/$(id -u)/com.aimap.server`
- 다시 켜기: `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.aimap.server.plist`
- 자동 실행을 아예 없애기: 멈춘 뒤 위 plist 파일을 지운다.

### AI 브리핑 켜기

프로젝트 폴더에 `.env` 파일을 만들고 Anthropic API 키를 적는다. 서버 재시작 없이 다음 요청부터 적용된다.

```
ANTHROPIC_API_KEY=sk-ant-...
```

- 키는 **이 프로젝트의 `.env`에 적은 것만** 쓴다. 서버를 띄운 프로그램(IDE, 데스크톱 앱 등)에서 물려받은 `ANTHROPIC_*` 환경변수는 일부러 무시한다.
- 브리핑은 누군가 페이지를 열었을 때 만들어지고 3시간 동안 재사용된다 (`BRIEFING_TTL_MINUTES`로 조정). 생성 중에는 이전 브리핑을 계속 보여준다.
- 주간 리포트가 비지 않도록, 서버가 켜져 있으면 아무도 보지 않아도 **하루 한 번** 브리핑을 만든다 (`BRIEFING_SCHEDULE_HOURS`, 기본 24, `0`이면 끈다). 브리핑 하나가 72시간을 다루므로 하루 한 번이면 빠지는 이슈가 없다. 이 때문에 키가 있으면 하루 1회 이상 비용이 든다.
- 한 주가 끝나면(월요일 0시, 한국 시간) 지난주 이슈로 주간 요약을 한 번 만든다. 이슈만 입력으로 쓰므로 브리핑 1회보다 훨씬 적게 든다. 이슈가 3개 미만인 주는 만들지 않는다.
- 모델은 `claude-opus-5-5` (`BRIEFING_MODEL`로 변경 가능). 1회 생성에 약 $0.2~0.3 (추정). 실제 토큰 사용량은 서버 로그와 `data/briefing.json`의 `usage`에 남는다.
- 실패하면 15분 동안 다시 시도하지 않는다 (잘못된 키나 장애로 비용이 반복되지 않도록).

### 샘플 브리핑으로 화면 보기 (API 키 없이)

```bash
npm run sample
```

`test/fixtures/briefing-sample.json`을 브리핑으로 보여준다. 실제 기사 제목을 사람이 직접 묶어 만든 예시이며, 화면에 "샘플"로 표시된다. 주간 리포트도 이 샘플로 메모리에만 만들어 보여주고(2026년 40주차), 실제 보관 파일은 건드리지 않는다.

## 데이터 점검 (자동 갱신)

서버가 켜져 있으면 1분 뒤 첫 점검을 하고, 이후 12시간마다(`WATCH_INTERVAL_HOURS`) 자동으로 확인한다. http://localhost:5173/admin.html 에서 결과를 보고 "지금 점검"도 할 수 있다.

| 점검 | 무엇을 | 결과 |
|---|---|---|
| CEO 변동 | Wikidata의 현재 CEO 중 **최근(마지막 검토일 60일 전 이후) 취임**한 사람이 우리 데이터와 다르면 | 변경 제안 |
| 신규 상장 | 비상장 기업 이름으로 Yahoo 검색 → 주요 거래소 보통주 중 이름이 단어 단위로 일치하고, 실제 거래 중이며, 1년 안에 상장한 종목이 있으면 | 변경 제안 |
| 종목 상태 | 상장사 종목명이 처음 본 이름과 달라졌거나, 시세 조회가 2회 연속 실패하면 | 신호 |
| 뉴스 신호 | 최근 14일 기업별 뉴스 제목에 교체·취임 / IPO·상장 / 인수·합병 / 모델 출시 표현이 있으면 | 신호 |
| 관계 제안 | 인수·합병 기사 제목에 지도의 두 기업이 함께 나오고, 그 둘 사이에 아직 같은 관계가 없으면 | 관계 추가 제안 |
| 모델 제안 | 출시 기사 제목에 타임라인에 없는 모델 버전(예: GPT-6.2, Solar Mini 4)이 나오면 | 모델 추가 제안 |
| 데이터센터·전력 소식 | AI 기업 뉴스 중 데이터센터·전력 계약 기사, 그리고 전력 회사 26곳을 "데이터센터"와 함께 검색한 기사 중 착공·가동·계약·증설·취소 같은 일이 있는 것. 기사마다 지도의 데이터센터·발전소·전력 회사를 이름으로 찾아 잇는다 | 신호 |
| Claude 검토 | (`.env`에 키가 있을 때만) 새 뉴스 신호를 현재 데이터·관계·모델과 비교해 실제 변경과 새 관계·모델만 구체적인 값으로 | 변경 제안 · 관계·모델 추가 제안 |
| Claude 검토 (데이터센터·전력) | (키가 있을 때만) 데이터센터·전력 소식을 지도의 장소 119곳과 비교해 이야기마다 어느 장소인지, 무슨 일인지(새 장소·건설·가동·증설·전력 계약·취소·지연), 지도와 다른지를 한 줄로 | 신호에 메모 |

- **변경 제안**은 지금 값과 제안 값, 근거 링크를 보여주고, 값을 고친 뒤 반영할 수 있다. 무시한 제안은 다시 나오지 않는다.
- **신호**는 기사를 보고 직접 고치거나(저장하면 신호도 닫힘) 무시한다. 무시하면 그 뒤에 나온 새 기사만 다시 알린다.
- 반영한 내용은 손으로 쓴 `companies.js`를 건드리지 않고 `public/data/overrides.js`(자동 생성)에 필드 단위로 쌓인다. 브라우저와 서버 모두 companies.js 위에 덮어써서 쓰고, "반영 이력"에서 기업별로 되돌릴 수 있다.
- 추가한 관계·모델도 `relations.js`·`models.js`는 그대로 두고 같은 `overrides.js`에 쌓여 각 목록 뒤에 붙는다. 그래서 페이지는 `companies.js` → `relations.js` → `models.js` → `overrides.js` 순서로 불러와야 한다. "반영 이력"의 "추가한 모델"·"추가한 관계"에서 하나씩 뺄 수 있다.
- **데이터센터·전력 소식**은 고치는 버튼 없이 알려 주기만 한다. 데이터센터는 Epoch 자료로 만든 생성 파일이고 발전소는 손으로 확인해 넣기 때문에, 지도와 다른 소식은 기사 출처를 확인한 뒤 `tools/datacenters/build.py`(`MANUAL`)나 `public/data/power.js`에 반영한다. 기사 아래 장소 칩은 지도에서 그 장소를 연다(`./#dc/<id>`, `./#plant/<id>`, `./#power/<id>`). 장소를 못 찾은 기사는 지도에 아직 없는 곳이거나 특정 장소 이야기가 아닐 수 있다.
  - 장소 찾기(`infraReader`): 프로젝트 이름(Hyperion, Fairwater Atlanta, 콜로서스 2 …)과 `SITE_ALIASES`의 고유 이름(Three Mile Island, 각 세종 …)은 그것만으로, 도시 이름처럼 흔한 단어는 그곳을 운영·사용하는 기업이나 전력 회사가 같은 제목에 나올 때만 잇는다.
- 점검 상태는 `data/watch.json`에 저장된다. 전체를 사람이 다시 검토했다면 `companies.js`의 `AI_DATA_VERIFIED` 날짜를 올린다.
- **배포 전 주의**: 점검 API(`/api/watch/*`)는 요청이 이 컴퓨터(127.0.0.1)에서 오고 같은 출처의 JSON일 때만 받는다. 리버스 프록시 뒤에 두면 모든 요청이 127.0.0.1로 보일 수 있으니, 공개 배포할 때는 인증을 붙이거나 이 경로를 막아야 한다.

## 기업 추가·수정

- `listings[].symbol`은 Yahoo Finance 심볼이다. 한국 `005930.KS`, 홍콩 `0700.HK`, 도쿄 `9984.T`, 대만 `2330.TW`, 암스테르담 `ASML.AS`, 프랑크푸르트 `SAP.DE`.

- 뉴스에 엉뚱한 기사가 섞이면 `news: { ko, en }`로 검색어를 지정한다 (예: Arm → `"Arm Holdings"`, Cursor → `"Cursor" AI coding`).

## 관계 추가·수정

`public/data/relations.js`의 `AI_RELATIONS`에 한 줄씩 추가한다. `from`·`to`는 companies.js의 id, `type`은 아래 중 하나다. 방향은 돈·물건·사람이 가는 쪽이다.

| type | 의미 | from → to |
|---|---|---|
| `invest` | 투자 | 투자자 → 투자받은 기업 |
| `supply` | 반도체·장비 공급 | 공급사 → 고객 |
| `cloud` | 클라우드·컴퓨팅 | 제공 → 사용 |
| `partner` | 제휴 | 방향 없음 |
| `alumni` | 출신·분사 | 출신 기업 → 새로 세운 기업 |
| `own` | 인수·자회사 | 모회사 → 자회사 |

`label`(한 줄 요약), `detail`(설명), `since`(`'2025'` 또는 `'2025-10'`), 확인한 기사가 있으면 `source: { title, url }`. 출처가 없으면 화면에서 두 회사 이름으로 뉴스 검색 링크를 대신 보여준다. 지도에 없는 회사(예: 월드랩스, Aleph Alpha)와의 관계는 담지 않는다.

### 인수·합병 기사에서 관계 제안 받기

데이터 점검이 인수·합병 신호의 기사 제목을 읽어 관계 추가를 제안한다. /admin.html "변경 제안" 탭에서 방향·종류·문구를 고쳐 "관계도에 추가"하면 바로 관계도에 들어간다 (새로고침). 인수·합병 신호 카드의 "관계도에 관계 직접 추가"로 손으로 넣을 수도 있다.

- **두 기업 찾기**: 제목에서 `name`·`nameKo`(` · `로 나눈 이름, 괄호 속 이름 포함)와 `aliases`를 찾는다. 영문 이름은 단어 단위로, 4자 이하(`Arm`, `Meta`)는 대소문자까지 맞아야 한다. 한글 이름은 조사가 붙으므로 부분 일치. 지도 기업이 **정확히 두 곳** 나온 제목만 쓴다. 기사에 다른 이름(예: 삼성, DeepMind)으로 자주 나오면 companies.js에 `aliases`를 더한다.
- **종류**: 지분·stake + 인수 → `invest`(지분 인수), 인수 → `own`, 합병 → `own`(신뢰도 낮음, 방향 확인 필요), 투자 → `invest`.
- **방향**: 먼저 나온 기업이 주체. "acquired by", "~에 인수돼", "투자 유치"처럼 수동형이면 뒤집는다.
- **거르는 것**: 추진·협상·검토·인수전·물음표 제목, 무산·철회·결렬 제목, 두 기업 사이에 같은 종류(또는 인수·자회사) 관계가 이미 있는 경우. `since`는 기사 날짜의 연도만 넣으니 실제 시점으로 고친다.
- 제목만 보고 추정하므로 반드시 검토한다. API 키가 있으면 Claude가 같은 기사를 맥락과 함께 읽고 관계를 따로 제안하고, 같은 두 기업에 대한 제목 기반 제안은 Claude 제안으로 바뀐다.

## 데이터센터 데이터 갱신

`public/data/datacenters.js`는 생성 파일이다. 고칠 내용은 `tools/datacenters/build.py`에 적고 다시 만든다.

```bash
python3 tools/datacenters/build.py --refresh
```

- Epoch AI의 [AI data centers](https://epoch.ai/data/ai-data-centers) 묶음(CC BY 4.0)을 내려받아(`tools/datacenters/epoch/`, git에서 제외) 데이터센터별로 지금 전력(오늘 이전의 마지막 추정치), 계획 최대 전력과 그 시점, 처음 가동한 때를 계산한다. 전력은 냉각까지 포함한 **시설 전체 전력**이다 (Epoch 순위표의 숫자는 IT 전력이라 더 작다).
- 상태: 지금 전력이 0이면 건설 중(공사 기록이 없으면 계획), 계획이 지금보다 5% 넘게 크면 일부 가동·증설 중, 아니면 가동.
- 운영·사용 기업은 지도 기업 id로 바꾼다. Epoch가 '확실(confident)'로 본 곳은 그대로, '유력(likely)'은 흐리게 "유력"으로 표시하고, '추측(speculative)'은 뺀다. 지도에 없는 회사는 이름만 보여준다.
- **확인된 곳**: 운영하거나 쓰는 기업 중 하나라도 확실하고, 건물이 실제로 있는(가동 중이거나 공사가 위성으로 확인된) 곳. 나머지(운영사 미공개, 유력뿐, 계획만 발표)는 기본 화면에서 빠지고 "전체"에서 흐리게 보인다.
- **숫자의 근거**(`basis`): Epoch 데이터는 지금 전력·가동 시점이 추정, 앞으로의 규모·시점이 예상이라 흐리게 보인다. 직접 보탠 곳은 회사 발표(`announced`)나 언론 보도(`reported`)로 표시한다.
- **근거 자료**: Epoch의 'Selected Sources'(곳마다 1~8개: 인허가 서류, 시공사·전력회사 자료, 공시, 기사)와 날짜별 위성 확인 메모(최근 3개 + 다음 예상 1개, 영어 원문)를 그대로 옮긴다. 직접 보탠 곳은 `MANUAL`의 `sources`에 근거를 2~3개씩 적는다.
- 새 Epoch 데이터센터가 생기면 먼저 `python3 tools/datacenters/geocode.py`로 좌표를 찾는다 (OpenStreetMap Nominatim, 초당 1건). 주소가 엉뚱한 곳으로 잡히면 `build.py`의 `GEO_FIX`에 도시 좌표를 적는다.
- 한글 이름(`NAME_KO`), 설명(`DESC`), Epoch에 없는 곳(`MANUAL`, 출처 필수)도 `build.py`에서 관리한다.

## 성능 비교 데이터 갱신

`public/data/benchmarks.js`는 생성 파일이다. 고칠 내용은 `tools/benchmarks/build.py`에 적고 다시 만든다. Epoch은 며칠마다 새 점수를 올린다.

```bash
python3 tools/benchmarks/build.py --refresh
```

- Epoch AI의 [Capabilities & benchmarking](https://epoch.ai/benchmarks) 묶음(CC BY 4.0)을 내려받는다(`tools/benchmarks/epoch/`, git에서 제외). 시험 문제와 외부 리더보드 점수의 권리는 각 시험을 만든 곳에 있다.
- 모델은 Epoch의 `model_group`으로 묶고, 같은 모델을 여러 설정(추론 강도·코딩 도구)으로 시험했으면 가장 높은 점수와 그 설정을 남긴다. 표기만 다른 이름("Qwen 3.7 Plus"와 "Qwen3.7-Plus")과 이름에 붙은 설정("_none")은 한 모델로 합치고, 합친 목록을 출력하니 잘못 합쳐진 게 없는지 본다.
- 오차 범위: Epoch이 표준오차를 준 시험은 점수 ± 1.96 × 표준오차(95%), ECI는 Epoch이 준 90% 구간. ARC-AGI-2·FrontierCode는 오차가 공개되지 않는다.
- 만든 곳은 Epoch의 조직 이름을 지도 기업 id로 바꾼다(`ORG_TO_COMPANY`). Epoch이 만든 곳을 비워 둔 모델은 이름으로 채운다(`NAME_MAKERS`, 예: `granite-` → IBM, 오픈 웨이트 여부 포함). 채우지 못하면 "maker unknown"으로 출력한다.
- 시험 설명·읽는 법·주의할 점·근거 링크는 `METRICS`에 있다. 문장은 각 시험의 Epoch 페이지나 만든 곳의 페이지에 있는 내용만 쓴다.

## 발전소·전력 회사 추가·수정

`public/data/power.js`에 손으로 적는다. 발전소는 AI 기업과의 계약이 공식 발표됐거나, 데이터센터 전용으로 짓는 것이 공시·보도로 확인된 곳만 넣고 `sources`에 근거를 1~3개 단다.

- `fuel`: `nuclear`(가동·재가동 원전) · `advanced`(SMR·4세대 원전·핵융합) · `gas`
- `status`: `operating` · `partial` · `restarting` · `construction` · `planned`(계획·승인). `planned`는 `certain: false`로 두면 "전체"에서만 흐리게 보인다.
- `mw`와 `basis`: 회사 발표·공시면 `ann`, 보도면 `rep`. 원전 계약은 발전소 전체가 아니라 계약 물량일 수 있으니 `deal`·`desc`에 밝힌다. 모르면 `null`(비공개로 표시).
- `buyers`: 전기를 사는 지도 기업 id, `datacenters`: 직접 전기를 받는 데이터센터 id(전력망 계약이면 비운다), `operator`: `AI_POWER_COMPANIES`의 id.
- 전력 회사의 `epochNames`는 데이터센터 데이터의 전력 공급사 이름이다. 이 이름으로 그 회사가 공급하는 데이터센터를 화면에서 찾는다. 특정 발전소에 묶이지 않은 계약(예: 구글–컨스텔레이션 890MW)은 회사의 `deals`에 적는다.

## 모델 추가·수정

`public/data/models.js`의 `AI_MODELS`에 한 줄씩 추가한다. 2022년 11월 ChatGPT 이후, 지도에 있는 기업의 모델만 담는다. 같은 날 나온 크기별 변형(mini·Pro 등)은 한 줄로 묶는다.

| 필드 | 내용 |
|---|---|
| `company` | companies.js의 id |
| `name` | 회사가 쓰는 모델 이름 (같은 회사 안에서 겹치지 않게) |
| `date` | 처음 공개된 날 `'2026-10-07'`, 일자를 모르면 `'2026-10'` |
| `kind` | `text`(언어·추론·멀티모달 대화) · `image` · `video`(영상·월드 모델) · `audio`(음성·음악) |
| `open` | 가중치를 내려받을 수 있으면 `true` (오픈 웨이트) |
| `major` | 업계 흐름을 바꾼 출시면 `true` (차트에 테두리, 목록에 "주요 출시") |
| `desc` | 무엇이 새로웠는지 한 줄 |
| `source` | 확인한 기사 `{ title, url }` (선택) |

2026년 항목은 위키백과·공식 발표·주요 매체로 날짜를 확인했고, 소규모 업데이트는 일부만 담았다. 그래서 연도별·기업별 출시 개수는 업계 실제 속도가 아니라 정리 범위를 반영한다 (화면에도 비율·개수 비교 지표는 두지 않았다).

### 출시 기사에서 모델 제안 받기

데이터 점검이 기업별 뉴스에서 출시 표현(launch·release·unveil·출시·공개…)이 있는 제목을 고르고, 그중 모델 이름이 나오는 것만 "모델 출시" 신호로 만든다. 제목에 **타임라인에 없는 버전**이 있으면 모델 추가를 제안한다. /admin.html에서 이름·날짜·종류·오픈 웨이트·설명을 고쳐 "타임라인에 추가"하면 바로 들어간다. 모델 출시 신호 카드의 "타임라인에 모델 직접 추가"로 손으로 넣을 수도 있다.

- **모델 이름 찾기**: models.js의 이름에서 첫 버전 앞부분을 "계열"로 뽑는다 (`Claude Opus 4.6` → Claude Opus, `Qwen3.5` → Qwen, `Kimi K2` → Kimi). 제목에서 계열 + (Mini·Pro 같은 단어 두 개까지) + 버전 + (Pro·Flash 같은 단어)를 찾는다. `GPT`·`SOLAR`처럼 대문자 계열은 대소문자를 가리지 않는다.
- **이미 있는 모델**: 단어 단위로 비교해 `GPT-6`은 `GPT-6 Sol · Luna`가 있으면, `GPT-5.5 Pro`는 `GPT-5.5`가 있으면 이미 있는 것으로 본다. 이미 있는 모델만 나오는 출시 기사는 신호도 만들지 않는다.
- **기업·종류·오픈 웨이트**: 그 계열의 가장 최근 모델을 따른다. 날짜는 가장 이른 기사 날짜, 설명은 기사 제목이라 반드시 고친다.
- **한글 이름**: '솔라 미니 4', '클로드 오퍼스 6', '제미나이 3.5 프로를'처럼 한글로 쓴 이름은 아는 단어(`KO_MODEL_WORDS`)를 영문으로 바꿔 읽는다. 단어 단위로만 바꾸므로 '드라마'·'프로젝트'는 건드리지 않는다. 새 계열이 한글로 자주 나오면 이 목록에 더한다.
- **거르는 것**: 루머·유출·예정·연기·물음표 제목.
- **자동 정리**: 제안한 모델·관계가 models.js·relations.js에 들어가거나 다른 경로로 추가되면, 그 제안은 관리 화면에서 저절로 닫힌다.

## 뉴스와 브리핑이 만들어지는 방식

**기업별 뉴스**
1. 기업별 검색어로 Google 뉴스 RSS의 최근 30일 기사를 가져온다 (3건 미만이면 기간 제한 없이 다시 검색).
2. 제목에 기업명(검색어의 핵심어)이 없는 기사, 시세 페이지는 버린다.
3. 관련도 상위 30건 중 제목이 거의 같은 기사를 하나로 묶고, 최신순 10건을 보여준다.

**AI 브리핑**
1. 모든 기업의 한국어·영어 뉴스에서 최근 72시간 기사를 모은다 (같은 기사는 하나로, 보통 200~600건).
2. Claude가 같은 사건을 다룬 제목들을 하나의 이슈로 묶고, 제목·2~3문장 요약·분야·중요도·관련 기업을 JSON으로 돌려준다. 요약은 **기사 제목에 있는 내용만** 쓰도록 지시한다.
3. 서버가 기사/기업 id를 실제 데이터와 대조해 맞지 않는 것은 버리고, 중요도순 최대 12개를 저장한다.

**브리핑 보관 (주간 리포트)**
1. 브리핑이 새로 만들어질 때마다 이슈를 `data/briefing-archive.json`에 넣는다. 400일 동안 보관한다.
2. 72시간 창이 겹치므로 같은 사건이 여러 브리핑에 다시 나온다. **기사 링크가 하나라도 겹치면 같은 이슈**로 보고 합친다: 제목·요약은 최신 것, 기사는 누적(최대 24건), 중요도는 높았던 쪽을 유지한다.
3. 이슈는 가장 이른 기사의 날짜(한국 시간)에 놓고, 주는 ISO 기준(월~일)으로 나눈다.
4. 주간 요약은 그 주에 보관된 이슈의 제목·요약만 Claude에 주고 새 사실을 더하지 말라고 지시한다.

- 관계도 레이아웃: d3 v7 (cdnjs, 관계도를 처음 열 때만 불러옴)
